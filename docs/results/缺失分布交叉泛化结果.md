# 缺失分布交叉泛化结果

> 2026-09-21 更新｜M0、K=20、seed=2024。本文只整理已生成并审计过的结果；原始 JSON 仍保留在 `outputs/`。

## 1. 评估协议

- 场景：`ETH-M / HOTEL-M / UNIV-M / ZARA1-M / ZARA2-M`。
- 历史 8 帧、未来 12 帧、`K=20`、米制；direct 结果不经过外部插补。
- `Easy`：历史缺失 0–4 帧；`Hard`：历史缺失 4–7 帧。
- 指标：`minADE20`、`minFDE20`、`ADE@1`、`FDE@1`、`MR`。
- 主表报告五场景宏平均；原始结果 JSON 同时保留场景、`missing_count` 和样本数明细。
- `Mixed`：Easy+Hard 数据集级 1:1 拼接，训练和验证均使用 Easy+Hard；不是按 `missing=0…7` 严格均衡。
- `Clean→Easy/Hard` 使用 Clean benchmark checkpoint 测试官方 TrajImpute release，属于跨数据协议 zero-shot；`Hard→Clean` 使用 Clean benchmark evaluator，不能与 direct 主表无标注混排。

## 4. 当前裁定

1. Clean→Easy/Hard 均显著劣于对应 train-adapt，完整数据训练不能自然获得缺失历史鲁棒性。
2. Easy→Hard 显著退化；将 Hard 样本纳入训练后，Mixed→Hard 恢复到 Hard→Hard 同一量级，训练分布失配得到确认。
3. Mixed→Hard 相对 Hard→Hard：`minADE20 +1.03%`、`minFDE20 +1.69%`、`ADE@1 +1.05%`、`FDE@1 +1.60%`、`MR −1.10%`。Mixed 与 Hard-specific 差距不大，应保留为有效 baseline/control，但尚未证明优于 Hard-specific。
4. Mixed→Easy 与 Hard→Easy 也处于同一量级：Mixed 的 `minADE20` 略低，但 `minFDE20` 和 MR 略高；不支持稳定优势结论。
5. Mixed→Hard 的 `missing=7` 尾部仍有明显退化，简单 Easy+Hard 拼接没有解决低证据、长时间外推问题。
6. 当前 `Mixed` 只改变训练数据分布，不能包装为 evidence-coverage-aware training；后续应比较公平 step/validation 对齐、severity-balanced 和 evidence-balanced 训练。
