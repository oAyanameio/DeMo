# 缺失历史预测实验方案

_实验方案记录 · 更新时间：2026-10-08 · 适用任务：TrajGap-Bench Mixed-direct · 基础模型：DeMo actor-only_

> **文档性质**：本文件是后续实验的实施方案，不代表其中任何候选已经验证有效。正式结果统一写入《实验总汇总》，并遵守本文件中的结果归档与主协议约束。

> **当前状态**：M0 是唯一滚动基线。由于 TrajGap-Bench 训练数据本身已经包含自然缺失，本方案不再额外人工删除 waypoint，也不实施依赖人工遮挡的 masked-motion reconstruction。主线收缩为 M0 → M1；只有 M1 证明自然缺失证据校准有效，且诊断仍指向关系交互问题时，才启动可选 M2。

## 1. 目标与边界

### 1.1 实验目标

本轮不再改造历史 Mamba 的 selective state transition、kernel 或 `dt`，也不重复已经判负的历史状态读取和共享编码器重复注入。实验只验证两个与现有自然缺失数据直接相关的增量：

1. **自然缺失证据校准**：利用历史 mask 派生的证据，改善高缺失样本的 mode ranking、MR、top-1 指标和不确定性表达；
2. **关系级动态交互**：若 M1 通过且误差诊断仍显示 focal–neighbor 关系是主要瓶颈，只替换一层 Scene Context Transformer 为关系级模块。

TWD 和 masked-motion reconstruction 从当前主线删除，原因是数据已经提供自然缺失；继续人工制造缺失会改变训练分布，而 reconstruction 需要额外人工遮挡才能定义监督，边际收益与归因价值不足。

### 1.2 明确不做的事项

本方案不包含以下改动：

- 不在训练、验证或测试阶段额外随机删除 waypoint；
- 不增加人工 `drop_mask`、waypoint dropping 概率或重采样逻辑；
- 不实施依赖人工遮挡的 masked-motion reconstruction head；
- 不在推理阶段先生成一条确定性历史插补轨迹，再把插补结果送入预测器；
- 不修改历史 Mamba 的 selective state transition、kernel 或 `dt` 计算；
- 不使用“最后有效 hidden state”替换现有 readout；该路线已有历史 screening 判负记录；
- 不把 `mask`、`gap`、`valid rate` 或 evidence summary 简单拼接到 actor token 或 Mode Query；
- 不一次性替换全部历史 Mamba 或全部 Scene Transformer；
- 不改变未来监督、K=20、损失评估口径和 TrajGap-Bench Mixed-direct 协议；
- 不把单个高缺失子组的改善写成整体方法有效。

## 2. 固定实验协议

除非本文件某一阶段另有说明，所有模型沿用以下设置：

| 项目 | 固定设置 |
|---|---|
| 数据协议 | TrajGap-Bench Mixed-direct |
| 数据组织 | Mixed train / val / test |
| 缺失来源 | TrajImpute 官方 release，直接使用缺失历史，不先独立插补 |
| 场景 | ETH-M、HOTEL-M、UNIV-M、ZARA1-M、ZARA2-M |
| 历史 / 未来长度 | 8 / 12 |
| 多模态数量 | K=20 |
| 训练采样 | `natural`；不做人工 waypoint dropping |
| batch size | 64 |
| epoch | 100 |
| optimizer | AdamW |
| learning rate | `1e-3` |
| warmup | 5 epochs |
| 精度 | `bf16` |
| checkpoint | `val_minFDE20` 最优 |
| 主指标 | `minADE20`、`minFDE20`、`MR` |
| 必报指标 | `ADE@1`、`FDE@1`、`b-minFDE20`、scene macro / micro |
| 缺失分组 | `valid_count`、`missing_count`、`anchor_lag`、`forecast_gap`、最长连续缺口、`E0–E3` |
| 随机种子 | 首轮 `2024`；通过筛选后补 `2025`、`2026` |

所有候选都必须与同一代码状态下的 M0 配对比较。若候选改变了输出后处理、损失或模型结构，必须使用同一 revision 重新生成 M0 对照，不能直接复用旧 revision 的 M0 数值作为严格因果对照。

## 3. 机制吸收边界

本方案只保留与当前问题直接匹配的机制，不照搬论文任务、数据集和完整网络：

| 设计来源 | 吸收内容 | 本项目中的使用边界 |
|---|---|---|
| *Uncertainty-Aware Pedestrian Trajectory Prediction via Distributional Diffusion*，Knowledge-Based Systems | 显式建模未来分布不确定性 | 不引入完整 diffusion；仅对 DeMo 已有的 mode logits 和 Laplace scale 做自然缺失证据条件化校准 |
| *Dynamic-Group-Aware Networks for Multi-Agent Trajectory Prediction with Relational Reasoning*，Neural Networks | 多尺度、关系级的群体交互 | 仅作为 M2 候选；不能退化成按邻居 valid rate 的全局 attention bias |

TWD 和 RecMamba 的训练人工删点/人工遮挡路线不进入当前方案。论文的具体分区和学校认定口径应在论文定稿前按目标年份目录复核；本文件只规定实验实现，不把引用论文的结果当作本项目结果。

## 4. 实验顺序总览

| 阶段 | 模型标签 | 主要改动 | 训练期 | 推理期 | 进入条件 |
|---|---|---|---|---|---|
| 基线 | M0 | 当前 DeMo，不增加新模块 | 原始 natural 缺失分布 | 原路径 | 当前代码状态下配对复验 |
| 1 | M1 | missingness-aware output calibration | 用自然缺失证据训练校准头 | 校准最终概率和尺度 | M0 配对复验完成 |
| 2 | M2（可选） | M1 + 1 个关系级动态多尺度模块 | 只替换 1 层 Scene Context | 保持 actor 集合语义 | M1 稳定收益且关系误差仍为主因 |

每个阶段先做单场景 smoke，再做五场景 Mixed 确认。M1 通过后补多种子；M2 不是默认必做。

## 5. M0：当前代码状态下的纯基线配对复验

### 5.1 目的

M0 不增加任何新模块，也不改变自然缺失数据。重新运行的原因是当前 `forecasting_module.py` 已修复 optimizer 参数分组：历史实现可能遗漏部分自定义 mixer/RMSNorm 的可训练权重，当前代码会将应训练参数正常纳入 AdamW。旧 M0 仍保留为历史结果，但不能作为 M1 的严格配对对照。

### 5.2 设置

- TWD 关闭，不增加人工缺失；
- reconstruction 关闭，不增加辅助头；
- calibration 关闭，使用原始 `new_pi`、`scal_new`；
- 使用当前 revision、seed `2024`、五场景 Mixed-direct；
- 保存完整配置、git revision、checkpoint、raw 输出和分组指标。

### 5.3 M0 验收

- 数据协议、场景数量、K=20、checkpoint 规则和评估脚本与候选完全一致；
- 自然缺失样本数量和缺失分组统计可复现；
- 训练、验证、测试不包含人工删点字段；
- 结果作为 M1 的唯一严格配对基线。

## 6. M1：自然缺失证据条件化的输出校准

### 6.1 假设

现有诊断显示，高缺失样本中可能已经存在接近 GT 的候选轨迹，但最高概率 mode 排序不可靠。因此 M1 不再改造历史共享表示，而是直接利用输入中已有的历史缺失证据，校准最终 mode 概率和 Laplace 尺度。

M1 不改变数据缺失分布，不新增 waypoint，不生成历史插补结果。

### 6.2 evidence 特征

只使用 focal actor 的历史 mask 派生字段，不使用位置、未来或 scene 标签：

```text
e = [
    valid_ratio,
    missing_ratio,
    anchor_lag / obs_len,
    forecast_gap / obs_len,
    max_missing_run / obs_len
]
```

其中：

- `valid_ratio`：focal 历史有效帧比例；
- `missing_ratio`：`1 - valid_ratio`；
- `anchor_lag`：最后有效观测距观测窗口末端的间隔；
- `forecast_gap`：从最后有效观测到未来第一步的时间间隔；
- `max_missing_run`：focal 历史最长连续缺失长度。

`max_missing_run` 若当前 batch 尚未提供，应在 `trajimpute_dataset.py` 和 collate 中补充为诊断字段；它只能由历史 mask 计算，不能重新读取未来或原始文件推断。

### 6.3 校准形式

第一版只校准最终输出 `new_pi` 和 `scal_new`，同时保留 raw 与 calibrated 两套输出，不改变候选轨迹均值 `new_y_hat`：

```text
log_tau   = missing_ratio · f_tau(e)
log_scale = missing_ratio · f_scale(e)

new_pi_cal  = new_pi / exp(log_tau)
scal_cal    = scal_new · exp(log_scale)
```

约束如下：

- `missing_ratio` 门控保证 all-valid 样本 `log_tau=0`、`log_scale=0`；
- `f_tau` 和 `f_scale` 最后一层零初始化，训练初始时与 M0 等价；
- `scal_cal` 第一版使用 `[B, 1, 1, 1]` 广播，不学习逐 mode、逐时间、逐坐标校准；
- temperature 和 scale 必须有限、为正且有上界保护；
- 校准只使用自然缺失历史证据，不读取未来、不使用 scene 标签。

校准头建议为：

```text
Linear(5 → 32) → GELU → Linear(32 → 1)
```

### 6.4 损失与实施文件

第一版不新增独立 calibration loss，直接将校准后的 `new_pi_cal`、`scal_cal` 接入最终分支已有的分类损失和 Laplace NLL；raw 分支保留原有损失，避免校准头单独承担全部训练信号。

涉及文件：

| 文件 | 实施措施 |
|---|---|
| `src/datamodule/trajimpute_dataset.py` | 提供 `max_missing_run` 等历史 mask 诊断字段；不增加人工删点字段 |
| `src/model/trajectory_forecaster.py` 或 `src/model/layers/structured_future_decoder.py` | 增加 evidence 校准头，输出 raw/calibrated 概率与尺度 |
| `src/model/forecasting_module.py` | 将 calibrated 输出接入最终损失，记录 raw/calibrated 指标；checkpoint 仍看 `val_minFDE20` |
| `conf/` 下对应模型配置 | 增加 calibration 开关和初始化/边界配置，默认关闭 |
| `tests/` | 验证 all-valid 恒等映射、有限正尺度、自然 mask 特征来源和 raw/calibrated 输出并存 |

### 6.5 M1 评估与门禁

验证和测试同时报告：

- raw `new_pi` 与 calibrated `new_pi_cal` 的 `MR`、`ADE@1`、`FDE@1`；
- raw/calibrated 的 `minADE20`、`minFDE20`、`b-minFDE20`；
- 各 evidence bin 的 mode entropy；
- 高缺失组的平均预测尺度；
- scene macro / micro 与完整历史组变化。

M1 只有同时满足以下条件，才进入 M2：

- all-valid 样本 raw/calibrated 输出逐位一致，或在预先声明的浮点误差范围内一致；
- 高缺失组的 `MR` 或 `b-minFDE20` 至少一项稳定改善；
- 不能以 best-of-20 改善掩盖 `ADE@1`、`FDE@1` 或 top-1 排序退化；
- 总体主指标不出现系统性恶化；
- scale 始终有限、为正且不爆炸；
- seed `2024/2025/2026` 至少两个方向一致；
- raw 与 calibrated 输出均保存，禁止只保留校准结果。

若 M1 只改善某个极端缺失子组，或只改善 best-of-20 而 top-1 恶化，则记录为校准失败，不启动 M2。

## 7. M2：关系级动态多尺度交互（可选）

### 7.1 启动条件

M2 不是默认必做。只有同时满足以下条件才启动：

- M1 在高缺失组和总体指标上均有稳定收益；
- 诊断仍显示 focal–neighbor 关系在缺失条件下是主要误差来源；
- 已排除单纯概率排序和尺度表达不足；
- 能够通过 actor permutation、padding 隔离和关系打乱测试。

### 7.2 模块形式

以 M1 为基线，只将 5 层 Scene Context Transformer 中的 1 层替换为关系级模块：

```text
2 层 Scene Transformer
    ↓
1 层 Dynamic Multi-scale Relation Block
    ↓
2 层 Scene Transformer
```

关系级输入建议包含：

```text
relative_position
relative_velocity
distance
relative_heading
focal-neighbor temporal overlap
focal-neighbor missing evidence
```

构造 3 类关系尺度：

1. 近邻 pairwise relation；
2. 中距离 group relation；
3. 场景级 group summary。

缺失可靠性只能调节具体 focal–neighbor 消息，不能直接按邻居 valid rate 给所有 focal 统一加权。actor token 是无序集合，禁止沿文件顺序使用 actor-axis Mamba 或其他顺序扫描。

### 7.3 M2 门禁

- actor permutation 后输出保持一致；
- padding actor 不改变有效 focal 的输出；
- 随机打乱 reliability feature 后性能应下降或至少改变，证明模块真正使用关系级可靠性；
- 相比 M1，不能只因增加参数量得到收益；
- 总体 `minADE20`、`minFDE20`、`MR` 不出现系统性恶化；
- 若只改善某一场景或某一缺失等级，停止扩展关系模块。

## 8. 运行目录与命名

建议统一使用以下输出目录，避免与历史 screening 混淆：

```text
outputs/trajgap_plan/
  M0_pair_seed2024/
  M1_calibration_seed2024/
  M2_relation_seed2024/
```

每个运行目录至少保存：

- 完整 Hydra 配置；
- git revision；
- 数据文件清单和数据协议；
- seed、batch、epoch、checkpoint 规则；
- raw/calibrated 输出定义（M1/M2）；
- 缺失分组统计；
- `results.json`、训练日志和最终 checkpoint；
- 该阶段是否通过门禁及其理由。

正式五场景确认的命令入口仍使用现有训练与评估脚本；新参数优先加入配置，不在 shell 脚本中复制一套新的训练逻辑。

## 9. 测试与审计清单

### 9.1 数据级

- 训练、验证、测试均不生成额外人工缺失；
- 不存在 `drop_mask`、waypoint dropping 概率或人工删点重采样；
- 官方缺失与有效历史 mask 语义一致；
- `x_valid_mask`、`x_gap_steps`、`x_last_valid_idx`、`max_missing_run` 一致；
- 原始有效历史样本约束不被破坏；
- actor 顺序和 scene 分组不变；
- 未修改未来坐标、未来 mask 和评估样本数量。

### 9.2 校准级

- all-valid 时 `new_pi_cal == new_pi`、`scal_cal == scal_new`；
- temperature 和 scale 始终有限且为正；
- raw/calibrated 输出同时保存；
- 校准头只使用 focal 历史 mask 派生字段；
- 不以 test 指标选择校准超参数；
- 关闭 calibration 后应退化为 M0 的原始输出和损失。

### 9.3 关系模块级

- actor permutation 不改变输出；
- padding actor 隔离；
- 关系特征随机打乱对照；
- 相对位置和相对速度为主，可靠性不能单独决定消息；
- 不使用 actor 文件顺序作为时序顺序；
- M2 只相对 M1 比较，不与旧 M0 直接做非配对归因。

## 11. 推荐执行顺序

最终执行顺序固定为：

```text
M0：当前代码状态下的纯 M0 配对复验
    ↓
M1：自然缺失证据条件化的 output calibration
    ↓ 通过且关系误差仍为主因
M2：只替换 1 层 dynamic multi-scale relation block（可选）
```

任何阶段未通过门禁，都停止向后叠加。TWD、人工删点和依赖人工遮挡的 reconstruction 不再作为当前主线实验；如未来重新提出，必须作为新的独立假设重新预注册，不能从本方案隐式恢复。
