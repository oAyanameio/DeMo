# DeMo 架构等价重构方案

_方案状态：待实施 · 研究对象：DeMo/M0 actor-only · 正式协议：TrajGap-Bench Mixed direct_

## 1. 目标与边界

本方案研究一个明确的工程与科学问题：

> 在保持输入、输出、训练目标和评测协议不变的前提下，将 DeMo/M0 的内部网络算子替换为另一套架构，能否保持相同的预测行为和性能？

这里的“等价替换”不是要求新模型逐元素复现旧模型，而是要求：

1. **输入契约等价**：历史帧数、未来帧数、坐标变换、actor padding、场景组织和现有输入字段不变。
2. **输出契约等价**：训练器、评估器和指标继续接收相同语义的多模态轨迹、概率和尺度输出。
3. **训练协议等价**：数据、seed、batch size、epoch、优化器、学习率、loss、checkpoint monitor 和精度设置不变。
4. **功能角色等价**：历史编码、场景交互、Mode/State 分解和 Hybrid coupling 的职责保持可对应。
5. **性能等价**：新架构不能以牺牲正式 benchmark 主指标或高缺失诊断为代价换取结构变化。

本方案不把“替换 Mamba/Transformer”本身定义为论文创新。若新架构只达到相同效果，其结论应是结构功能或算子可替代性；只有在保持效果的同时取得明确的参数量、显存、速度、稳定性或缺失鲁棒性收益时，才具有独立工程价值。

本方案不修改数据集，不重新定义 TrajGap-Bench，不把历史 Easy/Hard screening 重新设为正式主协议，也不把 DeMo 原有的 Mode/State 解耦包装为原创。

## 2. 当前 M0 参考架构

当前实现的主要接口和模块如下：

```text
输入历史特征 [B, N, 8, 4]
  = x_positions_diff(2) + x_velocity_diff(1) + x_valid_mask(1)
        |
        v
逐行人历史编码
  hist_embed_mlp -> 4 层单向 Mamba -> 末时刻读取
        |
        v
行人 token [B, N, 128]
  + 位置/朝向 embedding + actor type embedding
        |
        v
场景交互
  5 层全 agent Transformer
        |
        v
场景上下文 [B, N, 128]
        |
        +--> State Query 分支 [B, 12, 128]
        |      Cross-Attention -> 双向 Mamba -> state trajectory
        |
        +--> Mode Query 分支 [B, 20, 128]
        |      Cross-Attention/Self-Attention -> mode trajectory/probability
        |
        +--> Hybrid Coupling
               mode feature + state feature
               -> [B, 20, 12, 128]
               -> final trajectory/probability/scale
```

主要实现位置：

- 历史编码和场景交互：`src/model/model_forecast.py`
- 未来 State/Mode/Hybrid 解码：`src/model/layers/time_decoder.py`
- 训练损失和输出字段：`src/model/trainer_forecast.py`
- TrajGap 数据适配和 collate：`src/datamodule/trajimpute_dataset.py`

当前 M0 的历史输入维度虽然由适配器额外计算了 `x_gap_steps`、`x_anchor_lag_steps` 和 `x_forecast_gap_steps`，但它们不属于本次等价重构的新增输入。若候选使用这些字段，实验将同时改变输入特征，必须另立为“特征增量”实验，不能标记为纯架构替换。

## 3. 冻结的正式 benchmark

所有 A/B/C 方案均遵循当前 TrajGap-Bench 口径。

### 3.1 数据协议

```text
数据来源：TrajImpute 官方 Easy/Hard release
公开协议：TrajGap-Bench Mixed direct
训练：Mixed-train = Easy/train + Hard/train
验证：Mixed-val   = Easy/val   + Hard/val
测试：Mixed-test  = Easy/test  + Hard/test
输入：缺失历史直接输入，不经过外部插补
历史：8 帧
未来：12 帧
模式数：K=20
```

Easy/Hard 只作为底层 release 来源和 Mixed-test 内部诊断标签，不作为两个独立正式主榜。Clean 结果单独报告，不与 TrajGap-Bench Mixed 主结果混写。

### 3.2 冻结的训练与选点

| 项目 | 固定值 |
|---|---|
| 主链模型 | M0 单向历史编码配置；候选只替换规定架构边界 |
| seed | 2024 作为首轮筛选；通过后至少 3 个 seed 确认 |
| batch size | 64 |
| epochs | 100 |
| warmup | 5 epochs |
| optimizer | AdamW |
| learning rate | `1e-3` |
| weight decay | `1e-4` |
| precision | bf16 |
| K | 20 |
| checkpoint monitor | `val_minFDE20` |
| checkpoint 选择 | 仅使用 Mixed-val，不查看 Mixed-test 选点 |
| loss | 保持当前 M0 `Trainer.cal_loss()`，不新增或删除 loss 项 |

任何候选若改变 loss、训练采样、checkpoint monitor、输入字段或后处理，必须从“等价替换”降级为独立方法实验。

### 3.3 指标与等价门槛

正式主指标：

- `minFDE20`
- `minADE20`
- `MR`

必须同步保留的诊断指标：

- `ADE@1`
- `FDE@1`
- `b-minFDE20`
- 逐场景 macro/micro 结果
- `missing_count`、`valid_count`、`anchor_lag`、`forecast_gap` 和最长连续缺口分组

等价替换不以单个 aggregate 或单个 seed 判定。建议在 E0 基线复现前冻结以下工程门槛：

1. 三个主指标的 3-seed 五场景 macro mean 相对 M0 退化不超过 3%，且配对置信区间不支持稳定负向变化。
2. `ADE@1`、`FDE@1`、`MR` 和 `b-minFDE20` 不得出现与主指标方向相反的明显系统性退化；单项异常必须回到场景和缺失分组核查。
3. `missing_count` 高缺失组、`anchor_lag` 长间隔组和 `forecast_gap` 长缺口组不得整体恶化超过预先冻结的筛选阈值；具体阈值在 E0 产物审计后写入运行 manifest，不得读测试结果后再定。
4. 新模型必须通过 all-valid、terminal-missing、padding actor isolation 和 actor permutation 检查。

若新模型性能等价但参数量、显存、吞吐或稳定性没有改善，则结论仅为“可替代实现”，不进入论文方法主线。

## 4. 方案 A：仅替换历史编码器

### 4.1 研究问题

> M0 的历史条件表征是否依赖 4 层单向 Mamba，还是只要保留相同的历史输入和 actor-level token 接口，其他时序编码器也能达到等价效果？

### 4.2 冻结部分

以下部分全部保持不变：

- TrajGap 数据适配器、collate 和坐标变换；
- 历史输入字段及其维度 `[B,N,8,4]`；
- actor padding 语义；
- `x_centers`、朝向和 actor type embedding；
- 5 层全 agent Scene Transformer；
- 原始 `TimeDecoder`，包括 State、Mode、Hybrid 三个分支；
- `Trainer.cal_loss()`、checkpoint 选点、评估器和后处理；
- `K=20`、Mixed train/val/test 和所有指标。

### 4.3 可替换结构

候选编码器必须接收 `[B*N,8,4]`，输出 `[B*N,128]`，再恢复为 `[B,N,128]`。首轮只选一个替代算子，不能把多个算子堆成新模型。

推荐候选：

| 候选 | 结构 | 主要验证问题 |
|---|---|---|
| A-Transformer | 轻量 temporal Transformer encoder + 固定 temporal positional encoding | 短历史下全局时序注意力能否替代 Mamba |
| A-GRU | 多层 GRU 或 gated recurrent encoder | 经典递归状态是否足以保持 M0 表现 |
| A-TCN | 膨胀 1D temporal convolution + masked/global pooling | 局部多尺度时序是否足以覆盖 8 帧历史 |
| A-SSM-lite | 更小的标准 SSM/线性状态空间块 | Mamba 的选择性机制是否对该短序列必要 |

候选不得额外读取 gap 特征，不得新增重建头，不得加入邻居历史写入，不得修改 decoder。

### 4.4 A 方案的关键风险

- 历史时间轴只有 8 帧，增加复杂 temporal attention 可能只增加参数而无收益。
- 如果使用 temporal key padding mask，必须将其视为状态语义改变，不能再称为纯算子替换。
- 若替代编码器同时改变 pooling 方式，实验就同时改变 readout；应拆成独立控制。
- 训练新分支可能改变完整历史样本的共享表示，即使初始化时等价，也不能直接假定训练后等价。

### 4.5 A 方案验收

A 方案只有在以下条件满足后才进入 B 或 C：

1. forward 输出字段和所有形状与 M0 一致；
2. all-valid 输入通过等价性和 permutation 检查；
3. Mixed-test 主指标达到等价门槛；
4. 高缺失诊断没有系统性退化；
5. 至少一个工程维度明确改善，或形成有价值的“算子不敏感”结论。

A 方案不应被写成“提出新的缺失感知编码器”，因为它没有改变缺失信息的语义处理，只是替换历史编码算子。

## 5. 方案 B：仅替换未来解码器

### 5.1 研究问题

> 在保留 M0 的历史表征和场景交互的条件下，当前 TimeDecoder 的 State/Mode/Hybrid 实现是否可以由更简单的 factorized decoder 等价替代？

### 5.2 冻结部分

以下部分保持 M0 不变：

- 历史 MLP + 4 层单向 Mamba；
- actor token 和 Scene Transformer；
- `[B,N,128]` 场景上下文接口；
- 输入数据、训练 loss、优化协议和评估器；
- 邻居辅助预测的监督接口。

### 5.3 推荐重构结构

新 decoder 保留三个功能角色，但替换具体算子：

```text
focal scene token [B,128]
       |
       +--> state tokens [B,12,128]
       |      time embedding + scene cross-attention
       |
       +--> mode tokens [B,20,128]
       |      learned mode embedding + scene cross-attention
       |
       +--> factorized coupling
              z[k,t] = Fuse(mode[k], state[t], focal_context)
              mode-axis mixer + time-axis mixer
              -> final trajectory/probability/scale heads
```

推荐默认实现为：

- mode 轴使用轻量 self-attention 或 MLP mixer；
- time 轴使用 temporal Transformer、TCN 或共享 temporal MLP；
- `K×T` 表示通过显式 factorized fusion 构造，而不是一次展平后使用多组通用块；
- 轨迹头、概率头和 scale 头保持独立语义；
- 输出同时提供原始 mode 分支和 final hybrid 分支，以兼容当前 Trainer 的字段契约。

### 5.4 B 方案的关键风险

- 当前训练器最终使用 `new_y_hat` 和 `new_pi`，只替换中间 mode/state 分支不会改变正式结果；必须真正替换 final hybrid path。
- mode diversity 和 probability ranking 不是同一个问题。新 decoder 可能保持 `minFDE20`，但恶化 `ADE@1`、`FDE@1` 或 `MR`。
- 直接把 evidence 或 gap summary 加进 mode query 会同时改变输入语义，不属于本方案的纯 decoder 等价替换。
- 不能把普通 factorized decoder 的效果包装成新的 Mode/State 理论；DeMo 已经定义了该解耦。

### 5.5 B 方案验收

除通用等价门槛外，B 方案必须单独核对：

1. K 个候选的覆盖不能显著收缩；
2. top-1 概率选择不能系统性变差；
3. `MR` 和 `b-minFDE20` 不得被 `minFDE20` 的表面持平掩盖；
4. 未来序列的时间连续性不能明显恶化；
5. 计算量、显存或推理速度至少有一个明确改善，或证明当前复杂 Hybrid coupling 对本任务不是必要的。

## 6. 方案 C：完整架构重构

### 6.1 研究问题

> 能否用一套统一的 temporal-agent encoder、scene set encoder 和 factorized future decoder，完整替代 M0，同时保持 DeMo 的输入输出功能和 TrajGap-Bench 性能？

C 是 A 与 B 均通过后的累计重构，不是第一轮直接启动的模型。

### 6.2 目标结构

```text
历史轨迹 [B,N,8,4]
        |
        v
Temporal Agent Encoder
        |
agent tokens [B,N,C]
        |
        v
Permutation-aware Scene Set Encoder
        |
scene context [B,N,C]
        |
        v
Factorized Mode-State Decoder
        |
K=20 future distributions
        |
        v
兼容 M0 的 trajectory/probability/scale outputs
```

C 的默认目标不是增加模块，而是减少内部耦合：

- temporal actor encoding 与 scene interaction 分离；
- scene encoder 对 actor 集合保持 permutation-aware；
- mode 轴和 future-time 轴分开混合；
- final output head 只承担轨迹分布参数化，不隐藏额外的训练目标；
- 所有模块共享同一个 scene context 接口，便于 A/B 单独替换。

### 6.3 C 方案的实现原则

1. 新实现使用独立文件，不直接重写 M0，保留 M0 作为 reference implementation。
2. 新模型通过显式 adapter 输出当前 Trainer 需要的字段。
3. 首轮不得引入新的 missingness feature、reconstruction task、social loss 或采样策略。
4. 参数量、激活显存和训练步数与 M0 对齐；如果无法对齐，必须在 manifest 中记录并降级为工程比较。
5. 先用 M0 teacher 做短程蒸馏 smoke，再进行正式 Mixed 训练；蒸馏不能替代真实 benchmark 训练。
6. 进行 actor permutation、padding isolation、all-valid identity 和 terminal-missing 行为检查。

### 6.4 C 方案风险

C 同时改变历史状态、场景交互和未来解码，是最容易出现不可归因结果的方案。以下情况均不能直接解释为架构优越性：

- C 优于旧 M0，但 A/B 单独未通过；
- C 只在单一场景或单一 seed 改善；
- C 只改善 `minADE20`，但 `MR` 或 top-1 退化；
- C 改变了输入字段、loss 或训练曝光量；
- C 通过蒸馏结果好于未蒸馏 M0，却没有对应的训练控制。

C 只有在 A、B 的边界实验都完成后，才能作为完整架构重构进行评价。

## 7. 实验顺序与目录纪律

### 7.1 固定执行顺序

```text
E0  当前 M0 在当前代码 revision 下重建/审计基线
 |
 +--> A 仅替换历史编码器，保留原 Scene Transformer + TimeDecoder
 |
 +--> B 仅替换未来 decoder，保留原历史编码器 + Scene Transformer
 |
 +--> C 完整替换 encoder/scene/decoder
 |
 +--> D 可选：C + M0 teacher distillation
```

A 和 B 可以并行筛选，但各自必须从同一 M0 参考版本出发。C 不应在 A/B 尚未完成时启动。

### 7.2 输出目录

每个架构版本使用独立 output root，不覆盖 M0 或历史产物。例如：

```text
outputs/arch_equiv/
  m0_reference_seed2024/
  A_history_encoder_seed2024/
  B_future_decoder_seed2024/
  C_full_rebuild_seed2024/
  D_full_rebuild_distill_seed2024/
```

每个场景目录必须保存：

- `manifest.json`
- resolved Hydra config
- train log 和 `metrics.csv`
- best checkpoint 与 checkpoint monitor 值
- Mixed-test `results.json`
- git revision、环境、参数量和实际命令

候选不得复用已有 M0 checkpoint 作为正式结果，除非实验明确标为 zero-shot 或 distillation control。配对比较必须在相同代码状态、seed、数据和预算下完成。

## 9. 结论规则

### Go

- 输入、输出、协议和 manifest 完整一致；
- 主指标达到预先冻结的等价门槛；
- 高缺失和 top-1/MR 诊断没有系统性退化；
- 至少一个工程维度改善，或得出可复用的算子替代结论；
- 结果在至少 3 个 seed 和多数场景保持方向一致。

### No-Go

- 需要修改 benchmark 才能维持结果；
- 需要改变 loss、采样、checkpoint monitor 或输入特征才能恢复效果；
- 只在单一场景或单一 seed 有收益；
- `minADE20/minFDE20` 持平但 MR、FDE@1 或 b-minFDE20 明显恶化；
- 破坏 actor permutation、padding isolation 或 all-valid 行为；
- 完整重构结果无法归因到 A/B 的任何一个边界。

No-Go 后不继续堆叠同类模块。若等价重构没有工程收益，则保留 M0 作为主链，并将结论收敛为：当前任务性能主要由输入表示、训练分布、损失和未来分布校准共同决定，单纯替换历史/未来网络算子不足以带来可识别收益。

## 10. 相关工作与借鉴边界

以下工作说明相关架构方向已有先例，不能把通用组件直接称为原创：

- **DeMo**：Mode Query、State Query 和 Hybrid Coupling 是原始 DeMo 设计；本方案只把它们作为功能接口和对照结构。
- **GRU-D**：用 mask 和时间间隔建模缺失状态衰减；不能把一般 mask/decay 机制单独主张为新颖性。
- **MissFormer**：用 missing token 和 masked attention 处理不完整轨迹。
- **GC-VRNN**：用图空间编码、temporal decay 以及联合插补/预测处理缺失轨迹。
- **STGN-IT**：用 observation-state encoding、时空图和 GRU 支持 incomplete trajectory input。
- **MS-TIP**：用 masked Transformer、多尺度交互和 refinement 处理插补感知预测。
- **RealTraj**：用 miss-detection 模拟和 unmasking pretext 增强对观测错误的鲁棒性。

因此，A/B/C 的研究定位是：

```text
A：历史编码算子可替代性审计
B：未来结构化 decoder 的功能等价性审计
C：端到端架构重构与工程效率审计
```

除非后续实验显示新的、可解释且在 TrajGap-Bench 上稳定成立的机制增益，否则不将 A/B/C 包装成新的缺失感知方法。
