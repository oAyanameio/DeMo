# 证据条件化状态—分布耦合模型设计

> **文档性质**：模型设计方案，不是实验结果。
>
> **当前状态**：C1-A（last-valid readout）已完成单种子 Easy/Hard screening 与证据强度分组归因，继续保留为必要 control。C3（observed-write / gap-propagation）已完成首版实现、机制测试和 Hard 五场景 screening；相对 M0 有正向信号，但未超过 C1-A，且长 gap/valid_count=1 仍失败。C2 gap-only control 尚未完成，C4/C5 尚未实现，当前没有可写入论文主结果的创新结论。
>
> **研究任务**：基于不完整历史轨迹的无插补未来轨迹预测（imputation-free future trajectory forecasting under partially observed histories）。
>
> **基础模型**：M0（本模型），即当前 DeMo actor-only 实现与 TrajImpute direct 数据适配路径。

---

## 1. 设计结论

当前模型不能只继续增加 `mask`、gap feature、双向 Mamba 或普通社会注意力。建议将模型改造成一个统一的**证据条件化状态—分布耦合预测器**：

```text
不完整历史观测
    -> 证据门控状态传播
       Evidence-Gated State Propagation
    -> 证据可靠性表示
       Evidence Reliability Representation
    -> 可靠性条件化未来分布
       Reliability-Conditioned Multimodal Forecasting
```

核心机制是：

1. 有效观测可以写入时序状态；
2. 缺失帧只能推进时间状态，不能写入新的观测证据；
3. 同一组证据状态同时调节未来 mode 的概率排序和未来尺度；
4. 历史状态和未来分布的变化由同一观测过程条件解释。

本文不把以下内容单独包装为原创：

- `valid_mask` 拼接；
- 普通 mask-aware pooling；
- Mamba 或双向 Mamba；
- 普通 gap feature；
- GRU-D/UniTraj 风格时间衰减；
- DeMo 原有 Mode/State/Hybrid 解耦；
- 只增加一个 uncertainty head。

可主张的创新候选是：

> **将观测驱动的状态写入（observation-driven state writing）与缺口期间的时间传播（gap propagation）显式分离，并使用同一 evidence state 贯穿时序状态更新与未来多模态分布调节。**

该表述仍然是待验证的研究假设，不是已证实结论。

## 2. M0 代码事实与问题边界

### 2.1 当前历史编码路径

当前 `ModelForecast` 的历史路径为：

```text
x_positions_diff + x_velocity_diff + x_valid_mask
    -> hist_embed_mlp
    -> 4 层单向历史 Mamba
    -> 固定读取最后一个时间位置
    -> actor-level Scene Transformer
    -> TimeDecoder
```

对应代码位置：

- `src/model/model_forecast.py:38-60`：历史输入投影和历史 Mamba；
- `src/model/model_forecast.py:119-153`：有效性 mask 拼接、历史编码和最后时间位置读取；
- `src/model/model_forecast.py:173-182`：actor-level Scene Transformer；
- `src/model/model_forecast.py:198-208`：固定未来时间 query 和 TimeDecoder 调用；
- `src/model/layers/time_decoder.py:171-240`：State Query、Mode Query、Hybrid Coupling 及预测头。

### 2.2 M0 已经具备的能力

M0 已经不是完全不处理缺失的原始完整历史模型：

- 历史 token 中包含 `x_valid_mask`；
- 缺失位置经过占位处理，并由 mask 区分；
- 数据适配器按有效历史构造位移、速度和朝向；
- actor padding 使用 `x_key_valid_mask` 屏蔽；
- TrajImpute 适配器已经生成 gap、anchor lag 和 forecast gap 等字段。

因此，论文不能把“模型第一次看到缺失 mask”写成方法创新。

### 2.3 M0 的结构性不足

#### 2.3.1 缺失 token 仍可能更新历史状态

当前 mask 作为输入通道进入 MLP，但历史 Mamba 仍然处理完整时间序列。模型没有显式规定：

```text
有效帧：传播旧状态 + 写入新观测
缺失帧：只传播旧状态，不写入观测
```

缺失帧不是一个普通的低值观测。它表示在该时刻没有新的坐标证据。

#### 2.3.2 gap 字段没有进入 M0 的状态转移

TrajImpute 数据适配器已生成：

- `x_gap_steps`；
- `x_anchor_lag_steps`；
- `x_forecast_gap_steps`；
- `x_last_valid_idx`。

这些字段位于 `src/datamodule/trajimpute_dataset.py:282-353`，但当前 `ModelForecast` 的核心历史编码和 decoder query 没有系统消费它们。于是，两个相同的位移可能被模型看成同样的运动，即使它们分别跨越了不同长度的时间缺口。

#### 2.3.3 固定末端读取不能表达末端缺失

当前历史摘要使用：

```python
actor_feat = actor_feat[:, -1]
```

当历史末端缺失时，读取的是经过缺失 token 处理后的最后位置，而不是最后一个有效观测对应的状态。这是状态读取语义问题，不能仅通过增加 mask 通道保证修复。

#### 2.3.4 缺失证据没有显式条件化未来分布

当前缺失结构没有明确进入：

- mode probability `pi`；
- future scale `scal`；
- refined scale `scal_new`；
- mode query；
- state query 的可靠性条件。

这与已有结果中的失败现象相吻合：高缺失条件下，best-of-K 指标可能仍有可用候选，但最高概率 mode 和 MR 明显恶化。该现象提示模型需要改变未来分布的可靠性表达，而不仅是继续改善平均位置误差。

### 2.4 当前数据字段边界

`src/datamodule/trajimpute_dataset.py` 已提供下列可用字段：

```text
x_valid_mask
x_gap_steps
x_last_valid_idx
x_anchor_lag_steps
x_forecast_gap_steps
x_last_valid_angle
degenerate_heading
```

后续模型可以从这些字段构造 evidence state，但不得读取未来目标、测试标签或未来轨迹统计量。

## 3. 研究问题与方法假设

### 3.1 研究问题

给定不完整历史观测、历史有效性 mask 和观测时间结构，模型如何在不恢复一条确定的完整历史轨迹的情况下：

1. 传播历史运动状态；
2. 区分新观测和时间缺口；
3. 让未来多模态分布的概率排序与尺度适应可用证据；
4. 在高缺失和未见缺失模式下保持合理的预测可靠性。

形式化为：

\[
p_\theta(Y_{1:T_f} \mid X^{obs}_{1:T_h}, M_{1:T_h}, \Delta_{1:T_h}, C),
\]

其中：

- `X^obs`：可见历史位置或由有效端点构造的运动证据；
- `M`：历史观测有效性；
- `Delta`：观测间隔、gap 和 anchor freshness；
- `C`：社会上下文；
- `Y`：完整未来轨迹。

### 3.2 方法假设

**H1：状态写入假设**

缺失帧不应与有效帧共享完全相同的状态写入规则。把缺失帧限制为 propagation-only，能够减少占位 token 对历史运动状态的污染。

**H2：可靠性条件假设**

`valid_count`、`anchor_lag`、`forecast_gap`、最长缺口和 heading degeneracy 等证据状态，应当进入未来分布的概率排序或尺度，而不能只作为历史输入的附加通道。

**H3：状态—分布耦合假设**

如果状态传播和未来分布调节共享 evidence state，模型在低证据条件下的 top-1、MR、b-minFDE 和 coverage 应比只改历史输入更稳定。

以上假设需要通过 paired experiments、分组指标和负对照验证。它们不能由结构图本身直接证明。

## 4. ECDC 方法框架

### 4.1 总体结构

```text
历史位置/运动证据 + validity mask + time-gap metadata
                    |
                    v
         Evidence State Construction
                    |
        +-----------+-----------+
        |                       |
        v                       v
  State Propagation       Reliability State
  状态传播                可靠性表示
        |                       |
        +-----------+-----------+
                    v
       Scene Context Transformer
                    |
                    v
     Reliability-Conditioned TimeDecoder
                    |
                    v
       multimodal future distribution
```

ECDC 不是新的完整 decoder，也不替换 DeMo 的 Mode/State/Hybrid 设计。它是围绕 M0 的方法层改造：

- 历史侧改变状态传播语义；
- decoder 侧增加 reliability conditioning；
- 原有 loss、K、输出接口和主要 decoder 模块先保持不变。

### 4.2 Evidence State

建议第一版使用可解释、仅由输入 mask 派生的 evidence state：

\[
r_i = [
\rho_i,
\nu_i,
\ell_i,
\phi_i,
\gamma_i,
\delta_i
],
\]

其中：

- `rho`：valid ratio 或 valid count 的归一化值；
- `nu`：最长连续缺口或 max missing run；
- `ell`：anchor lag；
- `phi`：forecast gap；
- `gamma`：heading degeneracy；
- `delta`：当前时间步距最近有效观测的 gap。

推荐不要同时放入高度重复的 `valid_ratio` 和 `missing_ratio`，也不要把 `missing_count` 当作完整的 evidence state。缺失总量不能替代缺失位置、观测新鲜度和连续性。

#### 输入语义约束

- 有效帧的运动特征必须只由有效观测端点计算；
- 缺失坐标占位值不能进入运动差分；
- gap 必须以真实离散时间步表达；
- actor padding 的 evidence state 必须被屏蔽；
- heading 不可辨识时必须有显式退化标志；
- 不得读取未来坐标或未来 mask。

### 4.3 Evidence-Gated State Propagation

对 actor `i`、历史时刻 `t`，定义：

\[
\tilde h_{i,t} = P(h_{i,t-1}, \Delta_{i,t}),
\]

\[
 h_{i,t} = \tilde h_{i,t} + m_{i,t} \cdot U(\tilde h_{i,t}, o_{i,t}, r_{i,t}).
\]

其中：

- `P`：时间传播函数；
- `U`：观测写入函数；
- `m=1`：允许写入观测证据；
- `m=0`：只保留传播结果；
- `o`：有效端点构造的运动证据；
- `r`：当前 evidence state。

这一定义的关键不是“有一个 gate”，而是**write path 受 mask 约束**：

```text
valid frame   -> propagation + observation write
missing frame -> propagation only
```

### 4.4 第一版实现边界

不建议第一版直接修改 Mamba selective scan kernel。优先采用两级实现：

#### C2：gap-conditioned propagation control

在 Mamba 前对历史证据施加显式 gap control，作为 cheap/borrowed control：

```text
hist_embed_mlp
    -> gap-conditioned feature control
    -> M0 temporal Mamba
    -> mask-aware readout
```

它只验证 gap/decay 是否能解释失败，不作为最终原创机制。

#### C3：observed-write / gap-propagation state

在历史编码器中显式分开传播与写入：

```text
per-step evidence
    -> propagation branch
    -> valid-only observation write branch
    -> temporal state
```

工程上可先用逐步 wrapper 验证状态语义，再决定是否把传播规则融合到高效的批处理 Mamba 路径。不要为了保留单次 Mamba 调用而牺牲机制定义，也不要在没有机制测试的情况下把普通 feature scaling 叫作 evidence-gated state。

### 4.5 Mask-aware actor readout

C1 是必要的结构 control：

```text
last-valid state
+ valid-state summary
-> actor representation
```

它解决的是历史摘要选择问题，不是完整创新点。至少比较：

- M0：固定末端状态；
- C1-a：最后有效状态；
- C1-b：有效状态 mean pooling；
- C1-c：最后有效状态 + 有效 mean pooling。

C1 必须在末端缺失、前缀缺失、中间缺口和仅一帧有效时分别测试。

### 4.6 Reliability-Conditioned Multimodal Decoder

在历史状态获得 actor representation 后，构造：

\[
z_i = f_{rel}(r_i).
\]

第一版只采用加性、零初始化的条件分支。

#### 4.6.1 Mode query 条件化

当前 mode query 结构为：

```python
mode_query = encoding[:, 0]
mode = mode_query[:, None] + multi_modal_query
```

候选改造为：

\[
q'_{i,k} = q_{i,k} + A(r_i) + B(r_i) \odot e_k,
\]

其中 `e_k` 是 mode embedding，`A/B` 是 reliability conditioner。

这样 evidence state 可以改变候选 mode 的相对表示，而不是只对所有 mode 施加同一个全局缩放。

第一轮只测试 reliability 对 mode logits 或 mode query 的影响，不改变 mode 数量和 mode/state 解耦结构。

#### 4.6.2 Future scale 条件化

对 `scal` 和 `scal_new` 使用加性条件：

\[
s'_{i,k,t} = s_{i,k,t} + S(r_i).
\]

新增分支的最后一层必须零初始化，并在全局初始化后再次确认，使模型初始时与 M0 的输出路径等价。

禁止第一轮直接规定：

```text
缺失越多 -> 强制 entropy 越大
```

低证据通常意味着信息不足，但未来真实分布不一定只表现为均匀变宽。让模型学习条件关系，并使用 proper scoring、coverage、MR、b-minFDE 和 top-1 指标验证。

### 4.7 不改变的部分

首轮 ECDC 不改变：

- DeMo Mode/State/Hybrid 的原始语义；
- decoder 中已有的双向 state Mamba；
- `num_modes=20`；
- future horizon；
- Laplace loss 和原有分类/回归损失；
- checkpoint monitor `val_minFDE20`；
- TrajImpute direct 数据边界；
- submission 和 evaluator 输出接口。

如果同时改变这些部分，结果只能作为工程候选，不能作为 ECDC 的机制性因果证据。

## 5. 模型版本与实验顺序

所有模型版本从配对的 M0 backbone state 启动，不使用独立随机初始化比较。每个版本固定 decoder、loss、K、数据划分、训练预算和 checkpoint rule。

| 版本 | 新增内容 | 定位 | 是否可单独主张 |
|---|---|---|---|
| M0 | 当前 M0 | baseline | 否 |
| C1 | last-valid / mask-aware readout | 必要工程 control | 否 |
| C2 | gap-conditioned propagation/decay | cheap 或 borrowed control | 否 |
| C3 | observed-write + gap-propagation state | 核心模型候选 | 条件性 |
| C4 | C3 + reliability-conditioned mode query/logit | 状态—分布耦合候选 | 条件性 |
| C5 | C4 + reliability-conditioned scale | 完整 ECDC 候选 | 条件性 |
| C6 | evidence–motion dual-stream SSM | 后置结构扩展 | 暂不主张 |
| C7 | evidence-adaptive social compensation | 后置社会证据扩展 | 暂不主张 |
| C8 | latent motion prototype prior | 高风险探索模块 | 暂不主张 |

推荐顺序：

```text
M0
  -> C1: 先修复历史摘要读取
  -> C2: 验证 gap/decay 是否已解释失败
  -> C3: 验证 observed-write / gap-propagation
  -> C4: 验证 mode probability 是否随证据状态适配
  -> C5: 验证 future scale / reliability 表达
  -> C6: 若单流机制成立，再分离 evidence/motion 两条状态流
  -> C7: 若时间机制稳定，再测试证据自适应社会补偿
  -> C8: 最后再测试训练集潜空间运动原型先验
```

### 5.1 不建议现在做的模块

#### Dual motion/context state

暂不优先加入 dual state，原因是：

- 参数量和状态语义明显增加；
- 容易与已有多状态/双流设计重叠；
- 不能在 single-state gate 未通过前证明必要性；
- 可能把共享表示变化误判为 motion/context 分工收益。

只有 C3 已证明单状态的写入规则有效，且 simple decay 无法解释收益时，才考虑 dual state 作为后续结构扩展。

#### 同轮加入同步社会证据

社会模块必须后置。当前 actor-level Scene Transformer 已存在；如果同时修改 temporal state 和 social attention，就无法判断收益来自时间证据还是邻居 token 数量。

#### 同轮修改 loss

概率质量问题需要单独诊断。不要在 decoder conditioning 同时加入新的 calibration loss、Energy Score loss 或 entropy regularizer。

## 6. 代码实现边界

### 6.1 建议新增文件

```text
src/model/layers/evidence_state.py
src/model/layers/reliability_conditioner.py
```

`model_forecast.py` 只负责组装，不承载全部逐步状态逻辑。

### 6.2 `ModelForecast` 构造参数

建议使用显式开关，默认保持 M0：

```python
use_evidence_state: bool = False
use_reliability_conditioning: bool = False
evidence_mode: str = "none"
```

可选的版本语义：

```text
none              -> M0
mask_readout      -> C1
gap_control       -> C2
evidence_gate     -> C3
mode_condition    -> C4
full_ecdc         -> C5
```

不要通过 `model_version` 字符串在 forward 内部隐式分支；结构行为应由明确参数控制。

### 6.3 数据字段

数据适配器继续输出原始证据字段：

```text
x_valid_mask
x_gap_steps
x_last_valid_idx
x_anchor_lag_steps
x_forecast_gap_steps
x_last_valid_angle
degenerate_heading
```

可靠性向量可以在模型中根据这些字段构造，避免数据侧和模型侧各自维护一份可能漂移的派生逻辑。若新增 `x_max_missing_run` 或 `x_valid_count`，必须同步更新 collate 和真实 batch 测试。

### 6.4 初始化要求

新增可靠性条件分支必须：

1. 最后输出层 zero-init；
2. 在 `self.apply(self._init_weights)` 之后再次 zero-init；
3. 用复制 M0 state 的方式做 paired initialization；
4. 测试新增分支关闭时与 M0 的输出契约；
5. 分别测试初始化等价性与运行时 gate 是否生效。

不能用两个相同 seed、但不同参数数量的模型直接声称“初始化等价”。新增模块会消耗 RNG stream，必须复制已有 backbone state。

## 7. 必须通过的机制测试

### 7.1 输入语义测试

- **Invalid-coordinate perturbation**：只修改 mask 为无效的坐标占位值，输出不变；
- **Gap-length test**：端点位移相同、gap 不同，传播状态不同；
- **Gap-position test**：缺失数量相同但位置不同，模型表示不同；
- **One-valid-frame test**：只有一个有效历史帧时不出现 NaN，并保留 heading degenerate 标志；
- **Terminal-missing test**：末端缺失时不读取固定末端作为唯一可靠摘要；
- **All-valid test**：全有效输入下，C1-C5 的预期 identity 或受控差异符合设计；
- **Padding isolation**：在同一个 batch 内扰动 padding actor，真实 actor 输出不变；
- **Actor-order permutation**：置换邻居顺序不制造虚假收益。

### 7.2 状态机制测试

至少提供以下可观测量或测试 hook：

```text
propagation output
observation write output
effective write gate
state before/after invalid frame
state before/after valid frame
```

需要确认：

- invalid frame 的 observation write 为零或严格不生效；
- valid frame 的 write path 能产生梯度；
- gap 增长时传播分支确实接收到 gap；
- 仅关闭 propagation 或仅关闭 write 时，行为发生可解释变化。

如果无法观察和区分这两个路径，不能把模块命名为 observed-write / gap-propagation。

### 7.3 Decoder 条件测试

- reliability vector 置零；
- reliability vector 在 batch 内随机打乱；
- 只保留 valid count；
- 只保留 forecast gap；
- 去掉 anchor lag 和 max gap；
- reliability 条件进入 mode，但不进入 scale；
- reliability 条件进入 scale，但不进入 mode。

如果 shuffle reliability 后输出和指标基本不变，说明 decoder 没有使用有意义的 evidence state。

### 7.4 借鉴模块的包装动机

以下模块可以直接作为实现起点，但必须按“借鉴控制 → 机制验证 → 条件性方法主张”的顺序使用，不能把已有组件名称直接当作原创贡献。

| 模块 | 可借鉴机制 | 在本文中的包装动机 | 首要验证问题 |
|---|---|---|---|
| C2 Freshness-aware gap decay | GRU-D/UniTraj-BTS 式 mask、时间间隔与衰减 | 相同位移跨越不同缺口时，观测新鲜度应改变其状态影响 | simple gap/decay 是否已解释 C3 的主要收益 |
| C3 Observation-Selective Mamba | valid-only write + gap-only propagation | 缺失帧不是低值观测，而是“没有新的坐标证据” | 当前 wrapper 之外，是否需要真正改变 Mamba 内部状态写入 |
| C4 Evidence-conditioned mode | 可靠性向量进入 mode query/logit | 历史证据不足不仅影响表示，还应改变未来 mode 排序 | high-missing 下 top-1、MR、b-minFDE20 是否改善 |
| C5 Evidence-conditioned scale | 可靠性向量进入 future scale | 预测尺度应随证据质量自适应，而非强制统一变宽 | coverage、calibration、Energy Score 是否改善 |
| C6 Evidence–Motion dual stream | missing-aware dual-stream SSM | 将“运动内容”和“证据可靠性”分开建模，避免普通拼接混淆语义 | 单流 C3/C4 通过后，双流是否有独立增量 |
| C7 Evidence-adaptive social compensation | 缺失条件下的社会上下文加权 | focal 自身证据不足时增加邻居社会证据，完整历史时避免邻居覆盖自身证据 | 时间对齐、邻居打乱和 padding isolation 负对照是否通过 |
| C8 Latent motion prototype prior | 训练集潜空间 prototype retrieval | 缺失时提供多个运动先验，但不恢复唯一历史坐标 | prototype 是否改善长 gap 且不引入未来泄漏 |

包装原则：

1. C2 只能写成 borrowed control；C3 只有在内部 write path 真正受 mask 约束后，才可讨论 evidence-gated state 的机制贡献；
2. C4/C5 共同构成“状态—未来分布耦合”主线，优先于 dual state、社会模块和 prototype bank；
3. C6-C8 不得与 C3/C4 首轮同时训练，否则无法区分收益来自状态传播、分布条件化还是社会/原型先验；
4. 所有新增模块继续固定 decoder、loss、K、数据边界、checkpoint monitor 和 paired initialization。

## 8. 实验与晋级门槛

### 8.1 统一协议

沿用当前正式 direct 口径：

- ETH-M、HOTEL-M、UNIV-M、ZARA1-M、ZARA2-M；
- 历史 8 帧、未来 12 帧；
- Easy-direct 和 Hard-direct；
- 不经过外部插补；
- `K=20`；
- M0、候选模型、loss、monitor、数据边界保持一致；
- 首轮可 screening，进入主链前必须多场景和多种子确认。

当前 M0 结果与协议边界见《实验总汇总》和《缺失分布交叉泛化结果》，本文不重复改写这些结果。

### 8.2 必报指标

```text
minADE20
minFDE20
ADE@1
FDE@1
MR
b-minFDE20
```

ECDC 进入正式确认阶段后增加：

```text
Energy Score
endpoint/interval coverage
mode probability calibration
future velocity continuity
future acceleration/curvature continuity
```

`minADE20/minFDE20` 只说明 20 个候选中是否存在接近 GT 的轨迹，不能单独证明 mode probability 或 predictive uncertainty 正确。

### 8.3 必报分组

```text
scene
missing_count
valid_count
anchor_lag
forecast_gap
max_missing_run
heading_degenerate
missing pattern
```

同时报告五场景 macro 和样本 micro。两者结论冲突时写成 scene-dependent，不选择有利的聚合方式单独报告。

### 8.4 C2 晋级门槛

C2 只是 control，但必须回答：

- simple gap/decay 是否已解释高缺失失败；
- 相比 M0 是否只改善 train-adapt，还是也改善 zero-shot；
- 是否在 all-valid 或 missing=0 组引入回归；
- 是否只改善 best-of-K 而恶化 top-1 或 MR。

如果 C2 已经解释主要收益，C3 必须证明 observed-write 机制有额外价值，不能把 C2 的收益归入 ECDC。

### 8.5 C3 晋级门槛

C3 至少应满足：

1. `valid_count <= 2` 或 Hard `missing=6/7` 的关键指标改善；
2. 优于 M0 和 C2 的合理强对照；
3. `ADE@1/FDE@1/MR` 不发生明显牺牲；
4. Clean 或 Easy `missing=0` 在预注册容忍度内；
5. 五场景方向不能只由 ETH 单独驱动；
6. 机制测试证明 invalid frame 不会执行有效观测写入；
7. 不依赖未来信息、测试集调参或 actor 顺序。

若 C3 不超过 C2，停止继续添加 dual state 和社会模块。

### 8.6 C4/C5 晋级门槛

可靠性条件化至少改善以下一项，同时不明显损害其他保护指标：

- 高缺失 MR；
- `ADE@1/FDE@1`；
- b-minFDE20；
- Energy Score；
- coverage 或 calibration；
- `missing=6/7` 的 top-1 轨迹质量。

以下情况判定为概率质量失败：

```text
minFDE20 下降，
但 MR、ADE@1、coverage 或 b-minFDE20 明显恶化。
```

### 8.7 No-Go 条件

以下任一条件成立时，不把 ECDC 写成已验证模型创新：

- C3 不超过 simple gap/decay control；
- 只改善单一场景；
- all-valid 或 missing=0 组发生持续回归；
- reliability shuffle 后收益不变；
- C4/C5 只让候选变分散，但没有改善概率质量；
- 增益来自训练步数、参数量、validation composition 或 checkpoint 规则差异；
- 机制 hook 无法证明 invalid frame 与 valid frame 的 write path 不同。

## 9. 借鉴与创新边界

### 9.1 相关工作提供的边界

TrajImpute 将缺失历史作为行人轨迹数据与 benchmark 问题提出，主要聚焦缺失数据构造、插补及插补后预测评估。[1][5] 这支持本文使用 TrajImpute-derived direct protocol 研究无插补预测，但不能把数据集本身写成 ECDC 的模型创新。

MissFormer 研究了带 missing token 和 missing event 编码的不完整轨迹 filtering/prediction。[2] 因此，单独使用 mask token、缺失 token 或 Transformer attention 不能作为本文的原创边界。

POP 通过 partial-observation 的历史重构和 feature distillation 提升不完整观测下的预测能力。[3] 因此，若本文加入历史重构或 teacher-student distillation，应作为明确的 borrowed baseline 或另一个方法线，不能和 ECDC 混写。

MS-TIP 联合处理轨迹插补和未来预测，并使用交互建模、场景信息和 refinement 模块。[4] 本文主线不恢复唯一完整历史，也不把插补质量替代未来预测质量；ECDC 的任务边界仍是 direct/imputation-free future forecasting。

### 9.2 借鉴控制

下列内容可以作为强对照，但不能直接计入原创贡献：

| 控制 | 作用 | 论文定位 |
|---|---|---|
| mask concatenation | M0 当前基线 | baseline |
| last-valid / mask pooling | 修复摘要读取 | engineering control |
| GRU-D-style decay | 检验时间衰减解释 | borrowed control |
| UniTraj/BTS-style gap scaling | 检验方向/时间缩放解释 | borrowed control |
| missing token / ordinary attention mask | 检验 token 路径解释 | borrowed control |
| history reconstruction/distillation | 与恢复路线比较 | separate baseline |

### 9.3 ECDC 的可主张边界

只有当 C3-C5 逐级通过机制和性能门槛时，才可以考虑如下贡献表述：

1. **机制贡献**：将有效观测写入与缺口传播显式分离；
2. **条件建模贡献**：使用 evidence state 同时作用于历史状态传播和未来多模态分布；
3. **实证贡献**：在 direct、high-missing、top-1/probability-quality 和 unseen-pattern 分析中验证证据条件化的作用。

不能表述为：

- 首次处理缺失轨迹；
- 首次使用观测可靠性；
- 首次使用状态衰减；
- 首次对未来分布做 uncertainty conditioning；
- 首次将 Mamba 用于缺失轨迹。

## 10. 论文主张草案

### 10.1 中文版本

> 本文提出一种证据条件化的状态—分布耦合机制，用于不完整历史轨迹下的无插补未来轨迹预测。该机制将历史处理分解为有效观测驱动的状态写入与缺失区间内的时间传播，并利用同一证据状态调节未来多模态分布的 mode 排序和预测尺度，使历史状态演化与未来预测可靠性共同适应可用观测证据。该贡献仅在配对初始化、强对照、机制测试和多场景分组结果均通过后成立。

### 10.2 English version

> We propose an evidence-conditioned state–distribution coupling mechanism for imputation-free future trajectory forecasting from partially observed histories. The mechanism separates observation-driven state writing from temporal propagation across missing intervals, and uses the same evidence state to adapt multimodal mode ranking and predictive scale. The claim is conditional on paired initialization, strong controls, mechanism tests, and consistent multi-scene evidence.

### 10.3 贡献强度等级

| 等级 | 条件 | 可写内容 |
|---|---|---|
| L0 | 仅完成代码和 smoke test | engineering implementation |
| L1 | C1/C2 有收益 | mask/gap control 有效，不能写 ECDC 创新 |
| L2 | C3 超过 C2 且机制测试通过 | evidence-gated state 是模型候选贡献 |
| L3 | C4/C5 改善 top-1/probability quality 且跨场景稳定 | 可主张状态—分布耦合机制 |
| L4 | L3 + unseen-pattern、多种子、跨数据集一致 | 可形成完整论文方法贡献 |

## 11. 下一步实施顺序

```text
1. 冻结 M0 state contract 和 paired initialization 工具
2. 实现 C1：last-valid / mask-aware readout
3. 实现 C2：gap-conditioned control
4. 编写 C3 机制测试：invalid write、gap propagation、all-valid、padding isolation
5. 实现 C3：observed-write / gap-propagation state
6. 在 Easy screening 后检查 Hard tail 和 top-1/MR
7. 若 C3 晋级，实现 C4：reliability-conditioned mode
8. 若 C4 晋级，实现 C5：reliability-conditioned scale
9. 最后再考虑同步社会证据或 dual state
```

每个阶段都必须保留：

```text
resolved config
manifest
checkpoint
代码 revision
seed
train/val/test protocol
results JSON
分组指标
```

尚未完成正式实现、训练、消融或多种子确认前，ECDC 只能称为**模型设计候选**。
